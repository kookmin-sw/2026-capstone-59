# 요구사항 명세서(SRS) vs 사용자 스토리(User Story)

## 한 줄 정의

- **SRS(Software Requirements Specification)** — 정형 템플릿에 요구사항을 문서로 묶어낸 수십~수백 페이지짜리 요구사항 명세서. 추적성·검증에 강하다.
- **사용자 스토리(User Story)** — `~로서, ~를 할 수 있다, 그래야 ~` 한 줄 형식으로 쓰는 가벼운 요구사항 표현. Agile 환경에서 대화의 출발점으로 쓴다.

둘은 배타적 선택지가 아니라 조합할 수 있다. 4~6명 구간에선 **사용자 스토리 중심 + 짧은 SRS 보조**가 가장 흔한 형태다.

## 비교

| 항목 | SRS | 사용자 스토리 |
|---|---|---|
| 형식 | 정형 문서(IEEE 830 또는 ISO/IEC 29148 템플릿) | 한 줄 형식 (`As a [역할], I want [기능], so that [목적]`) |
| 분량 | 수십~수백 페이지 | 카드 또는 1~3줄 |
| 사용 상황 | 요구사항 안정·계약·법규 환경 | Agile·변동성 큰 환경 |
| 추적성 | 강함 (ID 부여, 매트릭스) | 백로그 도구로 보완 |
| 학습 비용 | 큼 | 작음 |

## 사용자 스토리 형식

`사용자로서 회원가입을 하고 싶다, 그래야 내 정보를 저장할 수 있기 때문이다.`

역할·기능·이유 세 조각이 한 줄에 들어오면 된다. INVEST 기준(Independent, Negotiable, Valuable, Estimable, Small, Testable)을 체크리스트로 쓰면 품질이 유지된다.

## 팀 규모별 권장 형태

- **1명** — 사용자 스토리만 5~10개 적는다. 도구는 README 한 섹션 또는 Notion 페이지. SRS 전체는 생략해도 되지만, 스토리 5개 이상은 반드시 있어야 무엇을 만들지 모호해지지 않는다.
- **2~3명** — 사용자 스토리 10~20개 + 짧은 SRS 요약 2~5페이지. 도구는 GitHub Issues 또는 Notion 백로그 + 짧은 README. SRS는 NFR과 핵심 제약만 담고, 세부 FR은 사용자 스토리로 분해한다. NFR은 한두 개라도 꼭 명시한다.
- **4~6명** — 정식 SRS 10~20페이지 + 사용자 스토리 백로그 15~30개. 도구는 SRS를 Word/Notion 한 페이지, 사용자 스토리를 Jira/Notion DB. SRS는 시스템 개요·NFR·핵심 제약 중심, FR은 사용자 스토리로 분해한다. 외부 제출 요구가 있을 가능성이 있으므로 정식 SRS 형태를 유지한다.
- **7~10명** — 정식 SRS + 스토리 매핑(Story Map). 도구는 SRS를 Confluence, 사용자 스토리를 Jira Epic-Story-Task 계층. SRS와 스토리를 추적성 매트릭스로 연결하고, SRS 변경 시 스토리 영향 검토 절차를 둔다.

## 흔한 실수

- **둘 다 안 쓰기** — 기능을 머릿속에만 두고 바로 코딩을 시작하면 팀원 간 해석이 갈려 결국 재작업이 된다. 최소 사용자 스토리 5~10개라도 텍스트로 남겨야 한다.
  - bad: 기능은 머릿속에만 두고 바로 코딩을 시작했다.
  - good: 사용자 스토리 7개를 README에 먼저 적어뒀다.
- **분량 채우기용 SRS** — 100페이지 SRS를 만들어두고 아무도 안 읽으면 코드와 동떨어진 거짓 문서가 된다. 10~20페이지 핵심 SRS + 활동하는 사용자 스토리 백로그 조합이 훨씬 가치 있다.
  - bad: 100페이지 SRS를 만들었지만 아무도 안 읽는다.
  - good: 15페이지 SRS에 살아있는 스토리 백로그를 붙였다.
- **사용자 스토리에 솔루션 박기** — "React 컴포넌트로 만든 폼을 사용해 회원가입하고 싶다"는 스토리가 아니라 설계다. 사용자 스토리는 "무엇·왜"만 담고, "어떻게(솔루션)"는 설계 단계로 넘긴다.
  - bad: React 폼으로 회원가입하고 싶다고 적었다.
  - good: 회원가입해서 내 정보를 저장하고 싶다고 적었다.

## 핵심 요약

4~6명 구간 디폴트는 **사용자 스토리 중심 + 짧은 SRS 보조**다. SRS는 시스템 개요·NFR·핵심 제약을 담고, 세부 FR은 사용자 스토리로 분해한다.
